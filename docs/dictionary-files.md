# 사전

원본 사전은 UTF-8 TSV 파일을 담은 폴더입니다. 저장소의 `dicts/`가 기본 사전입니다.

## 배포판과 git의 사전

| | 사전 | 버전 |
|---|---|---|
| 배포판(Releases) | `hdTrans\dicts.hdsnap` 한 파일. `dicts/`를 [컴파일한 것](#컴파일한-사전-hdsnap) | 옆의 `dicts.txt` |
| git에서 받은 것 | `dicts/` 폴더의 TSV | 없음(개발판으로 표시) |

엔진은 데이터 폴더(프로그램 옆 `hdTrans\`, 없으면 프로그램 폴더)에 `dicts.hdsnap`이 있으면 그것을 쓰고,
없으면 `dicts\` 폴더를 씁니다. 배포판에서 git의 TSV를 쓰려면 `dicts.hdsnap`과 `dicts.txt`를 지우고 저장소의
`dicts/` 폴더를 그 자리에 둡니다. 사전 TSV를 직접 고쳐 쓸 때도 이렇게 합니다. 사용자 사전(`user\`)은 어느 쪽이든 그대로 읽습니다.

## dicts/ 구성

| 파일 | 계층 | 내용 |
|---|---|---|
| `base.tsv` | `base` | 기본 사전: 일반 어휘, 어미, 조사, 조동사, 품사, 의미 코드 |
| `words.tsv` | `words` | 어휘 보충: 명사, 동사, 형용사, 부사, 복합어 |
| `words-idioms.tsv` | `words` | 관용구, 숙어, 사자성어 |
| `words-slang.tsv` | `words` | 속어, 구어, 인터넷 용어 |
| `words-variants.tsv` | `words` | 기존 단어의 다른 표기: 이표기, 가나 표기, 반복 부호 |
| `names.00.tsv` ~ `names.02.tsv` | `names` | 인명, 캐릭터, 지명, 단체, 작품 이름 (키 순으로 세 파일로 나눔) |
| `names-places.tsv` | `names` | 일본 지명: 역, 노선, 도도부현, 시정촌, 명소 |
| `kana.tsv` | `kana` | 한자 단어의 히라가나 표기 |

`pos`, `sem`, `gram` 열의 코드 뜻과 예는 [dictionary-codes.md](dictionary-codes.md), 사전 행을 고쳐 오역을 바로잡는 방법은
[fixing-translations.md](fixing-translations.md#사전-행)에 있습니다.

이 밖에 어미(`endings.tsv`), 구(`phrases.tsv`), 문형(`patterns.tsv`), 의미(`senses.tsv`) 표는 엔진에
내장되어 있어 따로 둘 필요가 없습니다.

## 내장 표

내장 표의 원본은 저장소의 `src/core/dict/builtin/*.tsv`이고, 기본 모드에서만 더하는 행은
`src/core/dict/builtin/extra/*.tsv`(번역문 철자 교정 `cleanup.tsv` 포함)에 있습니다. 빌드할 때
`cmake/builtin_tables.cmake`가 이 파일들을 C++ 소스로 바꿔 라이브러리에 넣으므로, 표를 고칠 때는
TSV만 고칩니다. 내장 표의 행은 모두 같은 파일 번호로 컴파일되므로, 키가 같은 행끼리는 `prio`가 같으면
파일과 상관없이 줄 번호가 작은 행이 이깁니다. 컴파일되지 않는 행이 하나라도 있으면 사전을 불러오지
못하므로 단위 테스트가 모든 내장 표를 컴파일해 봅니다.

`cleanup.tsv`는 `바꿀 글<TAB>새 글[<TAB>조건]` 줄로, 번역문을 앞에서부터 읽으며 그 자리에서 처음 맞는 줄로
바꿉니다. 조건 `final`은 앞 글자에 받침이 있을 때만, `attributive`는 앞이 받침 ㄴ, ㄹ로 끝나는 말과 공백
하나일 때만(갈 때에 → 갈 때) 바꿉니다. 바꾸지 않을 글은 같은 글로 바꾸는 줄을 앞에 둡니다(때에 따라).

### 의미 표 (senses.tsv)

한 행은 `일본어<TAB>한국어[<TAB>트리거<TAB>before|after|sentence[<TAB>품사]]`입니다.
품사는 `n`, `v`, `v1`, `v5`, `adj`, `na`, `p`(조사)이며, 생략하면 일본어 어미로 정합니다.
한국어는 기본형을 쓰고, `p`는 활용하지 않습니다. 트리거는 쉼표로 구분한 OR 조건이며,
같은 키에서 처음 맞는 행이 이깁니다. 트리거가 없는 행은 기본값입니다.

- 단어 트리거는 사전형으로 적습니다. `before`, `after`는 같은 절의 앞, 뒤 세 항목 이내,
  `sentence`는 문장 전체를 봅니다. 앞, 뒤 탐색은 다른 서술어와 절 경계를 넘지 않습니다.
- `sem:UHr`는 선택된 항목의 3바이트 의미 코드, `gram:Oq`는 2바이트 문법 태그를 검사합니다.
  코드 경계가 맞아야 하며, 선택되지 않은 후보는 검사하지 않습니다.
- `gram:Oq@を`는 `を` 바로 앞 명사에 `Oq`가 있을 때만 맞습니다. `@조사`는 `before`에서만
  쓰며, 조사의 항목도 실제 조사여야 합니다. 조사 자체의 뜻을 고를 때는 그 조사 앞 명사만 봅니다.
- `sem:VHn@に/gram:Rc`는 위 조건에 더해 `に` 뒤 첫 서술어의 `Rc`도 검사합니다. 여덟 항목
  이내에서 다른 서술어, 어미, 기호에 막히면 맞지 않습니다. 경계를 넘는 의존 관계 분석은 하지 않습니다.

예를 들어 다음 행은 사람 명사 뒤 `に`의 뒤에 수령 동사가 올 때 `에게`를 선호합니다.
조건이 맞지 않아도 다른 번역 후보를 버리지 않고 기존 규칙, 기본값을 그대로 씁니다.

```tsv
に	에게	sem:VHn@に/gram:Rc	before	p
聞く	묻다	gram:Oq@を	before	v:ㄷ
```

사전 `gram`의 연어 태그는 `Rc`(수령, 전달 동사), `Oq`(질문 내용), `Os`(인장, 문장),
`Ob`(버튼, 스위치), `Op`(사진), `Om`(끼니), `Of`(덮는 침구), `Od`(음료, 먹물),
`Og`(독기, 영기), `Or`(돌아갈 상태), `Rr`(돌아오다, 돌아가다)입니다.
일반 의미 코드는 그대로 두고 해당 뜻의 행에 태그를 덧붙입니다.
명시적인 단어 연어를 의미 부류보다 앞에 두어 좁은 조건을 우선할 수 있습니다.

### 낱말 부류 (classes.tsv)

`classes.tsv`는 엔진의 단계가 단어를 견주어 보는 이름 붙은 단어 집합입니다. 한 줄은 `부류<TAB>단어[<TAB>메모]`이고,
부류의 단어는 파일 순서대로 읽으며(앞에서부터 맞춰 보는 단계가 있음) 한 부류에 한 번만 나옵니다. 머리의
`//= 부류<TAB>설명` 줄이 부류마다 하나씩 쓰임새를 적습니다. 코드는 `dict::InClass("부류", 단어)`와
`dict::ClassMembers("부류")`로 읽습니다. 표에 없는 부류 이름은 컴파일되지 않고, 어느 코드도 부르지 않는 부류는 ctest
`dicts.classes`가 찾습니다.
사전으로 불러오지 않는 내장 표라서 고치면 사전 캐시도 다시 만듭니다.

### 구문 표 (constructions.tsv)

`constructions.tsv`는 `rewrites` 층에서 조사 같은 단어의 한국어를 앞뒤 단어로 고르는 행의 표입니다. 조건은 규칙의 본문
문법으로 쓰고 `classes.tsv`의 부류를 `@부류`로 부릅니다. 형식은 [rule-language.md](rule-language.md#구문-표-constructionstsv)에
있습니다. 사전으로 불러오지 않는 내장 표라서 고치면 사전 캐시도 다시 만듭니다.

### 복자 표 (masked.tsv)

`masked.tsv`는 복자(伏せ字)로 가린 단어의 표이며 사전으로 불러오지 않고 번역 경로가 직접 읽습니다. 한 줄은
`일본어<TAB>한국어<TAB>단어`입니다.

```
セッ○ス	섹○	섹스
ち○ちん	자○	자지
```

- 일본어의 `○`는 가림 기호 한 종류의 연속(○ ● ◯ 〇 ◎ × ✕ ＊ * ■ □ △ ▲ ◇ ◆)을 뜻하며, 히라가나와
  가타카나를 가리지 않습니다. 한국어의 `○` 자리에는 원문의 가림 기호가 그대로 들어갑니다
  (`セッ××ス` → `섹××`).
- 한국어가 가림 기호로 끝나면 뒤의 조사는 셋째 열 단어를 따릅니다(`섹○를`, `가○을`).
- `○` 한쪽에 가나가 없는 행(`○ナニー`)은 원문의 그쪽에도 가나가 없을 때만 맞습니다.
- 표에 없는 가타카나 단어는 가림 기호 양쪽이 가타카나일 때 가림 기호를 둔 채 읽는 대로 씁니다
  (`オ○ニ` → `오○니`). ×와 ✕는 이름을 잇는 기호(`A×B`)이기도 해서 이때 쓰지 않습니다.
- 사전 키가 가린 단어 전체를 덮으면 그 키가 이깁니다. 사용자 사전에 `オ○ニー<TAB>자위`를 두면
  `オ○ニー`는 `자위`가 됩니다. 이 줄은 적힌 가림 기호(여기서는 ○)에만 맞습니다.

## 불러오는 순서

- 사전 폴더 목록을 차례로 불러오며, 뒤 폴더가 앞 폴더를 덮어씁니다.
- 각 폴더에서는 최상위의 `*.tsv` 파일만 이름 순서로 읽습니다. 하위 폴더는 읽지 않습니다.
- 프로그램 폴더에 `hdTrans/` 디렉터리가 있으면 데이터 루트로 쓰고, 없으면 프로그램 폴더 자체를 씁니다.
  이름은 대소문자를 가리지 않습니다. 기본 사전은 `dicts.hdsnap` 또는 `dicts/`, 설정과 사용자 사전은 `user/`에 둡니다.
  Windows 배포는 `hdTrans/` 아래, macOS와 Linux CLI 배포는 프로그램 옆에 둡니다.
- CLI, C API, GUI와 `J2KEngine.dll`은 사전을 따로 지정하지 않으면 데이터 루트의 `dicts.hdsnap`, `dicts/`
  순서로 찾습니다. CLI는 둘 다 없으면 현재 폴더의 `dicts`를 씁니다. 설정의 `dicts`나 명시한 사전 목록이 우선합니다.
  선택한 `.hdsnap`이 잘못되었으면 TSV로 바꾸지 않고 실패합니다.
- 폴더 다음에 [사용자 사전 파일](#사용자-사전-파일)를 불러옵니다.
- 목록의 첫 항목이 `.hdsnap` 파일이면 [컴파일한 사전](#컴파일한-사전-hdsnap)입니다.

## 파일 머리줄

`dicts/`의 모든 파일은 다음 두 줄로 시작합니다.

```
#! layer=words
# 속어, 구어, 인터넷 용어 (JMdict, pixiv백과 용어)
```

- 첫 줄 `#! layer=NAME`(바이트 순서 표시 뒤에 와도 됨)이 파일의 계층을 정합니다. 이 줄이 없으면
  `base` 파일이고, 다른 `#!` 첫 줄은 불러오기를 실패시킵니다.
- 둘째 줄은 파일에 무엇이 들었는지 설명하는 `#` 주석입니다.

## 계층

| 계층 | 형식 | 의미 |
|---|---|---|
| `base` | 열 파일 | 기본 사전. 뒤 파일의 의미가 키와 품사 부류가 같은 앞 파일의 의미를 가립니다. 같은 키의 의미는 `prio`가 높은 순, 그다음 파일, 줄 순서 |
| `base` | 일반 파일 | 머리줄 없는 파일은 [사용자 사전](#사용자-사전) 형식으로 읽습니다. 컴파일되지 않는 줄이 있으면 불러오기가 실패합니다 |
| `words` | 열 파일 | 어휘 계층. 의미를 앞 파일의 의미에 더합니다. `replace` 플래그가 있는 의미만 같은 키, 부류의 앞 의미를 가립니다 |
| `names` | 열 파일 | 이름 계층. 앞 이름 파일은 가리지만 기본 사전의 의미는 가리지 않습니다. `、`나 `。`가 든 키, 활용형 키, 너무 긴 한국어의 의미는 버립니다. `replace`는 키의 표기를 다시 정합니다 |
| `user` | 열 파일 | 열 형식 사용자 사전. 기본 사전보다 먼저 맞춰 보며 기본 사전을 가리지 않습니다 |
| `kana` | 일반 파일 | `가나<TAB>한자 키<TAB>부류` 줄. 기본 사전 단어의 가나 표기 |
| `readings` | 일반 파일 | `일본어<TAB>읽기` 줄. 이름 읽기 표 (가나 또는 한글) |
| `prefilter`, `postfilter` | 일반 파일 | 번역 전 일본어와 번역 후 한국어를 고치는 필터 행. Ehnd 필터 형식([필터와 Ehnd 사전](#필터와-ehnd-사전)) |

열 파일인지는 내용으로 정합니다. 빈 줄과 `#` 주석이 아닌 첫 줄이 `key`로 시작하는 머리글이면 열
파일입니다. `kana`, `readings`, `prefilter`, `postfilter`는 일반 파일만, `base`가 아닌 나머지는 열
파일만 가능합니다.
정의: `src/core/dict/snapshot.h`.

### 열 파일

탭으로 구분하며 따옴표나 이스케이프는 없습니다. 첫 줄(머리줄, 주석 제외)은 열 이름이고, 열은 이름으로 찾으므로
순서는 자유입니다. `dicts/`의 열 파일은 다음 순서이고, `base.tsv`와 `lexical-benefactive.tsv`는
`key ko pos sem gram dict rule ctx note id raw prio` 순서입니다.

```
key	ko	pos	sem	gram	dict	rule	ctx	note	flags	prio	reading	id
```

- 필수 열: `key`(일본어), `ko`(한국어), `pos`(품사 코드, 예: `N110`), `id`
- 선택 열: `sem`(의미 코드), `gram`(문법 코드), `dict`(사전 코드), `rule`, `ctx`, `flags`, `prio`, `reading`.
  그 밖의 열은 무시합니다. 같은 이름의 열이 둘이면 오류입니다.
- 행의 필드가 머리글보다 적으면 나머지는 빈 값이고, 많으면 오류입니다. `rule`과 `prio`는 10진수입니다.
- `rule`: 이 행의 후보를 고를 때 실행하는 지역 규칙의 번호([rule-language.md](rule-language.md#지역-규칙l-사전-rule-열))
- `ctx`: 그 지역 규칙의 본문(`||1 &&3 S+1== "あそば" …`). 엔진이 `ctx` 열과 전역 규칙으로 규칙 프로그램을 조립합니다.
  `rule` 없는 본문, 해석되지 않는 본문, 같은 번호의 다른 본문은 `파일:줄`과 함께 불러오기를 실패시킵니다.
- `note`: 그 규칙의 설명. 읽지 않습니다.
- 품사 이름 표(`src/core/dict/pos_schema.tsv`)와 조건 이름 표(`src/core/dict/part_patterns.tsv`)는
  `python3 tools/pos-schema.py`가 각각 `pos_schema_gen.cpp`와 `part_patterns_gen.cpp`로 씁니다.
- 사전의 행이 규칙 번호를 가리키는데 그 본문을 가진 행이 하나도 없으면(예전 사전) 불러오기가 그 사실을 알립니다.
  엔진은 빈 프로그램을 조립해 지역 규칙 없이 번역하므로, `--verify-dicts`는 이것을 실패로 봅니다.
- `raw`: 원본 사전 레코드(16진수). 읽지 않습니다.
- `flags`: 공백으로 구분한 `xxx`, `kana`, `hidden`, `replace`, `llm`(효과 없음)

## 사용자 사전

사용자 사전은 데이터 루트의 `user/userdict*.txt`, `user/userdict*.tsv`([아래](#사용자-사전-파일))이거나, 사전 폴더에 둔 머리줄 없는
`.tsv` 파일입니다. UTF-8(BOM 허용), 한 줄에 한 항목:

```
일본어 <TAB> 한국어 [<TAB> 품사[:부류] [<TAB> 옵션]]
```

```
# 주석은 #이나 //로 시작합니다. 빈 줄은 무시합니다.
魔導具	마도구
蒼月	아오츠키	surname
ユキ	유키	name
走り回る	뛰어다니다	v5
冷たい	차갑다	adj
ふわふわ	폭신폭신/폭신폭신하다	ono
さん	씨	hon
```

`//`로 시작하는 필드부터 줄 끝까지도 주석입니다. 첫 줄의 `#!`은 주석이 아니라 머리줄입니다.
필드는 최대 4개입니다.

### 품사

| 품사 | 의미 |
|---|---|
| `n` (기본값) | 명사 |
| `phrase` | 고정 표현 |
| `name`, `surname` | 이름(또는 성명), 성. 둘 다 품사 `N130`, 의미 `QPNVHn`이고 문법 코드만 `Wb`(이름)와 `Wa`(성)로 다릅니다. 성과 이름이 나란히 올 때 성을 가리는 데 씁니다 |
| `place` | 땅이름. 품사 `N130`, 의미 `QCTVPl` |
| `intj`, `lead`, `open` | 감탄사 |
| `hon` | 경칭 접미사. 한국어를 비워 둘 수 있음 |
| `v`, `v1`, `v5` | 기본형 동사. `v1`은 일단(る) 동사, `v5`는 오단 동사로 고정. 한국어가 `하다`, `되다`로 끝나는 する 동사는 명사도 추가. `ない`로 끝나는 동사는 형용사로 처리 |
| `adj` | 기본형 い형용사 |
| `na` | 형용동사. 한국어를 `형용사/부사`로 주면 `일본어+に`를 부사로 추가 |
| `adv`, `ono` | 부사와 그 する 동사. 한국어는 `부사/동사 기본형` |
| `end`, `pat` | 문장 끝 어미(문장 끝 서술어에만), 문형. `書く/쓰다`, `高い/높다`, `静か/조용하다`, `学生/학생`의 예문으로 적음: `書いたじゃん<TAB>썼잖아<TAB>end` |

`v`, `v1`, `v5`, `adj`, `na`에는 콜론 뒤에 활용 부류를 줄 수 있습니다: `규칙`, `하다`, `되다`, `이다`,
`ㄹ`, `ㅂ`, `ㄷ`, `ㅅ`, `르`, `러`, `ㅎ`, `우`, `으`. 생략하면 철자로 정합니다(듣다 ㄷ, 돕다 ㅂ, 짓다 ㅅ,
푸다 우, 받침 ㄹ, 르, 으 어간, 나머지는 규칙).

### 옵션

공백으로 구분한 `키=값` 또는 플래그입니다.

| 옵션 | 의미 |
|---|---|
| `prio=N` | 키 길이가 같은 항목 사이의 순서 (높을수록 먼저) |
| `final=v\|c\|l` | 한국어의 조사 부류: 모음, 자음, ㄹ |
| `attr=CODES` | 품사 기본값 대신 쓸 의미 코드 |
| `gattr=CODES` | 품사 기본값 대신 쓸 문법 코드 |
| `force` | 더 긴 기본 사전 키 안에서도 기본 후보보다 먼저 |
| `hidden` | 읽기만 하고 불러오지 않음 |
| `space`, `attach` | `hon` 줄: 경칭 앞 띄어쓰기 (기본 `attach`) |
| `register=R` | `end` 줄: 해당 말투의 서술어에만 (`plain`, `casual`, `polite`, `formal`, `archaic` 또는 `해라`, `해`, `해요`, `합쇼`, `하오`) |
| `stative` | `end` 줄: 상태 서술어에만. 같은 어미의 일반 줄보다 앞에 둠 |
| `neg=LEMMA` | `v`, `adj` 줄: 이 단어를 부정하는 한국어 동사 |
| `exclaim` | 내장 `phrases.tsv`의 `intj` 줄: 감탄. 물음표 앞에서는 소리로 읽지 않고 단어로 읽음 (よかった 다행이다, よかった？ 좋았어?) |
| `predicate` | `exclaim` 줄: 한자나 가타카나 명사＋は, が와 쉼표 뒤에서도 단어로 읽음 (あの頃は、よかった 좋았다) |

정의: `src/core/userdict/userdict.h`.

### 사용자 사전 파일

- 데이터 루트의 `user/`에서 이름이 `userdict`로 시작하고 `.txt`나 `.tsv`로 끝나는 파일을 모두 읽습니다.
  대소문자는 구별하지 않고 하위 폴더는 읽지 않습니다. 소문자 파일 이름의 바이트 순서로 읽으며 같은 항목은 뒤 파일이 우선합니다.
  배포본의 `userdict.example.txt`도 읽지만 주석만 있습니다. 새 항목은 `userdict.txt` 같은 별도 파일에 적으세요.
  옛 배치에서는 프로그램 옆 `userdict.tsv`를 먼저 읽습니다.
- `user/hdtrans.config.yaml`의 `userdict: path` 또는 `userdict: [first.tsv, second.txt, folder]`는 기본 탐색을 대신합니다.
  폴더에서는 같은 파일 이름 규칙으로 찾고, 목록 순서대로 읽습니다. 상대 경로는 설정 파일 기준입니다. 빈 문자열이나 빈 목록은 끕니다.
  CLI의 `-userdict PATH`도 파일이나 폴더를 받으며 여러 번 줄 수 있습니다. CLI 인자가 설정을 대신합니다.
- 사전 폴더 다음에 읽습니다. 머리줄은 없어도 되고, 있으면 `#! layer=user`여야 합니다.
  일반 파일은 같은 키와 품사의 앞 항목을 대신하며, 열 파일은 `user` 계층으로 캐시 없이 읽습니다.
- 잘못된 파일만 빼고 다른 파일은 읽습니다. 오류는 `파일:줄: 이유`로 CLI의 표준 오류, C API의
  `hdTrans_UserDictError`, J2KEngine.dll과 GUI의 디버거 출력에 나옵니다. 명시한 파일이 하나뿐인 CLI 호출은 그 파일 오류 때 실패합니다.
- 불러온 뒤 파일을 열어 두지 않으므로 실행 중에도 편집, 이름 바꾸기, 삭제가 가능합니다.

자동 다시 읽기(`UserReload::Auto`, 두 DLL과 GUI에서 켜짐, CLI에서 꺼짐):

- 번역을 시작할 때 1초에 한 번까지 파일 목록과 크기, 수정 시각을 확인해 추가, 변경, 삭제를 반영합니다.
- 사전 폴더와 함께 백그라운드에서 읽고 준비되면 한 번에 바꿉니다. 그동안은 이전 사전을 쓰며,
  새 사전을 받는 세션은 문맥 기억을 지웁니다. 오류 파일은 다시 바뀔 때까지 재시도하지 않습니다.
- 사용자 사전이 전부 잘못된 판이면 이전 사전을 유지합니다. 시작할 때 잘못된 파일은 빼고 열며, 고쳐 저장하면 반영됩니다.
- `J2K_ReloadUserDict`와 `hdTrans_Reload`는 설정까지 바로 다시 읽습니다.

### 사용자 사전 쓰기

- CLI: `user/userdict.txt` 등에 적거나 `-userdict first.tsv -userdict second.txt`로 지정합니다.
- C API, J2KEngine.dll, GUI: `user/`의 파일을 자동 반영합니다. 다른 경로는 공통 설정의 `userdict`로 지정합니다.

## 필터와 Ehnd 사전

Ehnd(이지트랜스 확장)의 전처리, 후처리 필터, SkipLayer, 사용자 사전을 그대로 쓸 수 있습니다. 형식과
적용 순서는 [ehnd-compat.md](ehnd-compat.md)에 있습니다.

- 기존 Ehnd 폴더: 설정 파일의 `ehnd: true`로 프로그램 옆 `Ehnd` 폴더를 켜거나 `ehnd: 경로`로 지정합니다.
  CLI `-ehnd DIR`, C API `hdTrans_OpenEhnd`, C++ `Engine::OpenEhnd`로도 켤 수 있습니다.
  `PreFilter*.txt`, `PostFilter*.txt`, `SkipLayer*.txt`, `UserDict*.txt`를 Ehnd와 같은 순서로 읽습니다.
  꿀도르 같은 Ehnd 사전은 `dicts/`에 들어 있지 않고 기본으로 켜지지 않습니다.
- 새 필터: 사전 폴더에 첫 줄이 `#! layer=prefilter` 또는 `#! layer=postfilter`인 파일을 둡니다. 행은
  Ehnd 필터 행과 같습니다.

```
#! layer=postfilter
# 말투 고치기
하였다	했다	20000000	0
 +([.,!?])	$1	20000000	1
```

- 열은 `원문<TAB>바꿀 글<TAB>차수[<TAB>정규식 여부]`입니다. 차수가 작은 행부터, 같은 차수는 읽은 순서로
  적용합니다. 정규식은 Ehnd처럼 Perl 문법(PCRE2)이며 고정 길이 lookbehind `(?<=…)`도 씁니다.
- 정규식이 안 되는 줄 같은 잘못된 줄은 건너뛰고, CLI는 표준 오류로 알립니다.

## 캐시

처음 불러온 사전은 컴파일한 캐시로 저장되어 다음부터 빠르게 열립니다.

- 위치: Windows `%LOCALAPPDATA%\hdtrans\cache`, macOS `~/Library/Caches/hdtrans`, Linux
  `$XDG_CACHE_HOME/hdtrans` 또는 `~/.cache/hdtrans`. `HDTRANS_CACHE_DIR`(절대 경로)로 바꿀 수 있습니다.
- 캐시는 사전 폴더 목록, 데이터 버전, 포인터 크기, 엔진 데이터와 컴파일러 식별값으로 구분됩니다.
  같은 폴더 목록이라도 다른 빌드는 다른 캐시를 씁니다.
- CLI는 캐시를 만들어 저장합니다. C API와 `J2KEngine.dll`은 있는 캐시를 읽기만 하고 새로 저장하지
  않습니다. DLL에서 쓸 캐시는 같은 빌드의 CLI로 같은 폴더 목록을 주어 미리 만듭니다:
  `hdtrans -dicts dicts -compile-dicts` (만든 캐시 경로나 `up to date`를 출력).
- 캐시 검사는 원본 파일의 크기, 시각, 파일 식별값만 봅니다. 이 값이 그대로인 채 내용만 바뀌었다면
  `-verify-dicts` 또는 `HDTRANS_VERIFY_DICTS=1`로 내용까지 확인합니다.
- 캐시 끄기: `-no-cache`, `HDTRANS_SNAPSHOT=off`, 또는 `HDTRANS_CACHE_DIR`를 빈 값, 상대 경로, `off`로.
- 저장된 캐시 세대는 그 자리에서 덮어쓰거나 자르면 안 됩니다. 손상이 확인된 세대는 저장하지 않는
  모드에서도 `.bad` 표시를 남기고 이름을 바꿀 수 있습니다.

## 컴파일한 사전 (.hdsnap)

기본 사전을 `dicts.hdsnap` 하나로 묶어 원본 TSV 폴더 없이 불러올 수 있습니다. 열 사전은 미리 컴파일하고,
일반 사전, 가나 표기, 이름 읽기와 기본 전후처리 필터도 함께 담습니다. 배포판과 [웹 데모](web.md)가 이 파일을 씁니다.

```sh
hdtrans --dicts dicts --compile-snapshot "$PWD/build/dicts.hdsnap"
hdtrans --dicts "$PWD/build/dicts.hdsnap" --in in.txt
```

- `--compile-snapshot FILE`은 기본 사전을 FILE에 컴파일하고 종료합니다. 별도 사용자 사전 파일은 넣지 않습니다.
  FILE이 있는 폴더는 심볼릭 링크가 아니어야 합니다.
- 사전 목록(`--dicts`, `hdTrans_Initialize`)에 `.hdsnap` 파일 하나만 넘기면 내장된 기본 사전을 읽습니다.
  원본 TSV나 폴더는 필요 없고 사전 캐시도 쓰지 않습니다. 사용자 사전은 별도로 읽습니다.
- 기존 호출과의 호환을 위해 `.hdsnap` 뒤에 폴더를 지정할 수도 있습니다. 이때 열 사전은 스냅샷에서 읽고,
  일반 사전과 필터는 내장 내용 대신 지정한 폴더에서 다시 읽습니다.
- 형식은 고정 폭 리틀 엔디언이라 포인터 크기나 컴파일러와 관계없이 같은 엔진 데이터(같은 `src/core/`)로
  빌드한 엔진이면 읽습니다. 64비트 CLI로 컴파일한 파일을 32비트 DLL이나 WebAssembly가 읽을 수 있습니다.
  엔진 데이터가 다르면 불러오기가 실패합니다.
- 열 형식 사용자 사전은 함께 쓸 수 없습니다(불러오기 실패, 엔진은 사용자 사전 없이 시작).
- 원본 TSV와 맞는지는 확인하지 않습니다. TSV를 고쳤으면 다시 컴파일합니다. 손상된 파일은 불러오기를
  실패시키며 캐시와 달리 이름을 바꾸지 않습니다.
